## 关键经验

- **抽离样式到 partial 时用 `@mixin` 比 `@function` 或纯 CSS 更合适**——因为 mixin 能正确处理 `:deep()` 等 scoped 穿透选择器
- **每个 partial 文件命名加下划线前缀**（`_shared.scss` / `_env-tabs.scss`）是 SCSS 社区约定，防止被误编译为独立 CSS
- **`loadPaths: ['node_modules']`** 是 Vite 的默认行为，partial 内部若使用 `@use` 引用 npm 包，需要在 `vite.config.ts` 的 `css.preprocessorOptions.scss.loadPaths` 中显式配置
- **相对路径 `@use '../styles/xxx'`** 在 Vue SFC 中以 .vue 文件位置为基准

## 关键经验（补充）

- **`#1677ff1a` 这种 4 字节 hex** 实际是 `#1677ff` + `1a`（10% alpha）。CSS 解析器支持，但 var() 体系下需要转为 `rgba(22, 119, 255, 0.1)` 才可参与暗色模式
- **`#fff` 改 `var(--bg-color)` 在某些场景错位**：如 active 态图标需要强对比色，保留 `#fff` 即可。判断标准：色值在视觉上是否需要"恒定对比"而非"响应主题"

### 决策背景
审计时发现的"两套 CSS 变量系统"原本计划"全量合并"，但深入调查后发现：

**app.ts 实际不会自动初始化**：
- `applyTheme()` 只在用户**主动打开设置面板**时由 `appStore.initialize()` 触发
- `App.vue` 启动时**没有**调用 `initialize()`，所以 app.ts 的 15 个变量在页面打开时根本不存在
- theme 系统在 `App.vue:16` `useThemeStore()` 同步执行，**已立刻注入** 50+ 个 token

**两套系统的 `--primary-color` 格式冲突**：
- app.ts 注入：`--primary-color: #1677ff`（hex 字符串）
- theme 注入：`--primary-color: 22 119 255`（rgb 三元组，无 rgb() 包裹）
- 后注入的覆盖前者
- **CodeEditor.vue:346** 写的是 `rgba(var(--primary-color), 0.1)` —— 这种语法**只接受 rgb 三元组**，所以如果 app.ts 覆盖了它，hover 效果会**直接失效**

### 子任务 A 改动（1 文件）
- `src/stores/app.ts` cssVars 对象删除 `--primary-color` 键
- 添加注释说明为什么（防止后续维护者重新加上）
- 40+ 处 `var(--primary-color)` 引用**全部**走 theme 系统的 rgb 三元组注入

### 子任务 B 改动（1 文件）
- `src/stores/app.ts` 删除 `applyLanguage` 中的 `langText` 死代码（11 行）
- 该变量定义后从未被引用，纯 dead code

### 验证
- vite build 2.16s 通过
- 没有破坏 `var(--primary-color)` 的任何引用
- 0 个组件需要改动

### 关键经验
- **"全量合并"不等于"高质量重构"**：表面看两套系统有重复，但深入时序分析发现它们各管一摊（app 管布局、theme 管色板），合并反而会引入回归
- **CSS 变量同名最危险**：不是功能错乱，而是**后注入者静默覆盖前者**，肉眼很难发现
- **`rgba(var(--xxx), 0.1)` 是排查"同名不同义"的探针**：如果项目代码里出现这种语法，说明有地方依赖了 rgb 三元组格式
- **运行时注入的变量不会出现在构建产物里**：`dist/assets/index-*.css` 中搜不到 `--primary-color` 是正常现象，不能据此判断"变量没起作用"
