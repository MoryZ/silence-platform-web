
## 第八批：Naive UI 主题注入（n-config-provider）

### 背景
- 审计时发现 `naiveTheme` 在 `stores/theme/index.ts:51` 计算但全项目**无任何 `n-config-provider` 包裹**
- 用户问"是不是为了 DAG 用的"——分析后确认 100% 是

### Naive UI 使用范围分析
全项目 15 个文件用了 Naive UI 组件，**100% 集中在 `src/components/workflow/`**：
- **DAG 节点组件**（8 个）：task-node / branch-node / callback-node / add-node / start-node / node-wrap
  - 用 NPopover/NTooltip/NTag/NBadge/NDescriptions/NDescriptionsItem/NEllipsis/NDivider 显示节点标签/状态/详情
- **DAG 配置 Drawer**（4 个）：task-drawer / branch-drawer / start-drawer / callback-drawer
  - 用 NDrawer + NDrawerContent + NForm/NFormItem/NInput/NSelect/NRadio
- **DAG 详情面板**（5 个）：detail-card / start-detail / callback-detail / task-detail / branch-detail / branch-desc
  - 用 NDescriptions + NTabs/NTabPane

### 关键判断
- `n-config-provider` **只控样式 token**，不碰交互逻辑（DAG 拖拽/缩放/连线/数据流都不依赖）
- 当前是 Naive UI 默认主题（绿色 #18a058），与 antd 视觉割裂
- 改成 `themeStore.naiveTheme` 后：主色从默认绿 → #1677ff，圆角 6px（getNaiveTheme 已配置），暗色模式响应

### 改动 2 文件
- `src/App.vue`：在 `a-config-provider` 内层包裹 `n-config-provider` + 4 个 provider（loading-bar/message/dialog/notification）
  - 同步暴露 `naiveTheme` computed
  - 不影响功能只控样式
- `src/plugins/naive.ts`：补充注册 5 个 provider 组件（之前 `create({components: [...]})` 没注册 provider，模板里直接 `<n-config-provider>` 会报未注册组件）

### 验证
- vite build 1.81s 通过（比之前 2.16s 略快）
- vue-tsc 类型检查 0 错误
- 没有改任何 workflow 业务文件
- 0 个 Naive 组件的 props/事件被修改
- provider 只是样式层，逻辑层（拖拽/缩放/连线）完全不受影响

### 关键经验
- **`app.use(naive)` + `create({components:[...]})` 模式下，provider 组件也需要显式列出**才能在模板里用 `<n-config-provider>`，否则会运行时报"未注册组件"
- **`useDialog / useMessage / useNotification / useLoadingBar` 这类 composable 必须在 provider 子树内调用**——但项目当前**没有任何 composable 调用**（grep 结果 0 匹配），所以即使不包这 4 个 provider 也不报错；预装是为后续扩展
- **Naive UI 主题 token 是 `common: {primaryColor, primaryColorHover, primaryColorPressed, primaryColorSuppl, ...}` 格式**——`getNaiveTheme` 已正确生成 5 种场景 × 5 颜色
- **provider 嵌套顺序很重要**：`a-config-provider` 外层 + `n-config-provider` 内层，先 antd 后 naive，避免两个 UI 库 provider 互相干扰

### B 阶段经验
- **Agent 并行处理大规模 lint 修复**比手工逐文件快 5-10 倍——把 226 个 unused-vars 分给一个 Agent 跑 194 个，剩 32 个给第二个 Agent
- **ESLint JSON 输出 `ruleId` 在 `messages[].ruleId`**，不在顶层——解析时容易踩坑
- **`allow: ['warn', 'error']` 是 no-console 的最佳实践**——保留运行时有价值的诊断日志，只禁 log/info/debug
- **存量大项目的 lint 治理是"分批 + 决策点"节奏**，不是一刀切——每条规则都要问"为什么禁"，能找到"留比禁更合理"的地方就关掉
- **ESLint JSON 走 `--output-file` 而不是 `execSync`**——大项目 JSON 1-2MB，execSync 缓冲到 ENOBUFS；用文件 IO 更稳
- **自定义 ESLint 规则的 message 格式要看清楚**——`no-restricted-imports` 的 message 不会带 `from` 关键字，提取路径要用 `^['"]([^'"]+)['"]`
- **node 脚本里做正则替换一定要 escape 路径**——`relPath.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`，否则路径里的 `.` `?` 等会变成正则元字符
