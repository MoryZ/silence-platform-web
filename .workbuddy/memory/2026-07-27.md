# 2026-07-27 工作日志

## 第十批：两套 CSS 变量系统全量合并

### 背景
项目存在两套独立的 CSS 变量注入系统，并行运行但互不同步：
- **System A** (`stores/app.ts`): 布局/菜单/背景色，直接值格式 (hex/rgba)，通过 `root.style.setProperty()` inline 注入，暗色用 `data-theme` 属性
- **System B** (`stores/theme/`): 色板/Naive UI/语义色，RGB 三元组格式 (`22 119 255`)，通过 `<style id="theme-vars">` 标签注入，暗色用 `.dark` 类

### 3 个冲突点
1. **暗色模式不同步** — `data-theme` 属性 (A) vs `.dark` 类 (B)，两条触发链路独立运行
2. **SettingsDrawer 死代码** — `:root[data-theme='dark/light']` CSS 块被 app.ts inline style 覆盖
3. **命名重叠** — `--component-background` vs `--container-bg-color` 等同义不同名

### 改动 4 文件

#### 1. `src/stores/app.ts` — 同步暗色模式
- 新增 import: `toggleHtmlClass` from `@/utils/common` + `DARK_CLASS` from `@/constants/app`
- 在 `applyTheme()` 中设置 `data-theme` 后，同步调用 `toggleHtmlClass(DARK_CLASS)` 切换 `.dark` 类
- 效果：用户通过 SettingsDrawer 切换主题时，两套系统同时更新

#### 2. `src/components/SettingsDrawer.vue` — 删死代码
- 移除 `:root[data-theme='dark']` 和 `:root[data-theme='light']` 两个 CSS 块（共 12 行）
- 这些变量已被 app.ts 的 inline style 覆盖，是死代码

#### 3. `src/assets/main.css` — 添加静态 fallback
- 在 `:root` 中新增 14 个 System A 变量的 light 默认值
- 新增 `:root[data-theme='dark']` 块，提供 dark 默认值
- 作用：JS 注入前的首次渲染 fallback，避免 FOUC

#### 4. `src/styles/_theme-map.scss` — 文档化两层架构
- 在文件顶部新增 40 行架构注释，说明：
  - System A 和 System B 的职责边界
  - 注入方式/值格式/暗色模式机制差异
  - 命名对照表（同义不同名的变量）
  - 选用规则（什么时候用 A 什么时候用 B）

#### 5. `CODE_STYLE.md` — 新增 §2.6 CSS 变量使用规范
- System A / System B 的属性表格
- 选用规则代码示例（透明度用 B，直接引用用 A，色阶用 B，SCSS 用 _theme-map）
- 命名对照表 + "不能合并"的原因说明

### 关键判断
- **不能简单合并命名**：两套系统的值格式不同（直接值 vs RGB 三元组），合并会导致 `rgba(var(--xxx), 0.1)` 语法失效
- **不是竞争是互补**：System A 管布局色（直接引用），System B 管色板（需要透明度/色阶）
- **SettingsDrawer 的 CSS 块不是"死代码"而是"过期 fallback"**：移到 main.css 后仍然作为 JS 注入前的静态默认值
